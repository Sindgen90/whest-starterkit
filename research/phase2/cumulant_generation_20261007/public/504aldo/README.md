# whest-p2-cumulant-k3

Team 504aldo's Phase 2 estimators for the ARC White-Box Estimation Challenge 2026
(WhestBench): a factorized K=3 cumulant-propagation chain with a memoryless fourth-cumulant
regeneration, an age-gated shared subspace for old third-cumulant sources, and
Strassen-Winograd block products, written entirely in flopscope ops (pure-Python stdlib +
the flopscope client, as the Phase 2 rules require).

Live best: submission #330093 (V29), public LB 5.40e-9 adjusted, raw final-layer MSE 2.13e-8,
C/B 0.2526, rank ~10/139 on 2026-09-10. The write-up that explains all of this is
`docs/community_post.md`, posted on the competition forum on 2026-09-09:
https://discourse.aicrowd.com/t/everything-we-tried-a-factorized-k-3-cumulant-propagation-estimator-at-0-25-x-b-where-its-flops-go-and-25-measured-dead-ends-team-504aldo-rank-10/18218

TRANSPARENCY: every file in this repository was generated by an LLM (Claude, Anthropic) in
interactive sessions directed by the author. The author set the directions, ran every
experiment, read every number and decided what to ship. The code is deciphered, not opaque:
`docs/derivation_code_map.md` maps every mechanism to the equations and the code block.

## Layout

- `estimators/` -- the shipped versions, one self-contained file each (no data files needed):
  `estimator_v16b.py` (exact 7 -> 4 restructure) -> `v17` (kappa4 regeneration) -> `v18`
  (D21 feedback) -> `v19` (final-layer trim) -> `v22` (shared basis) -> `v24` (nested tier)
  -> `v25` (adaptive lambda; the METHOD) -> `v26`/`v27`/`v28`/`v29` (Strassen + residual
  engineering; same arithmetic, cheaper bill). `estimator_v29_ns.py` = V29 with
  flopscope namespaces for the per-family cost ledger. To submit one: copy it to
  `estimator.py` in the starter kit and run `whest validate` / `whest run`.
- `generators/` -- `make_vNN.py`: each version is an asserted textual patch of the previous
  one (the diffs ARE the change log). `lam_*` = the fit data of the lambda table (8 public
  MLPs, see the write-up).
- `harness/` -- local measurement: `dump_mini_mlps_p2.py` (builds the 8 ground-truth dumps
  from the public v2-phase2 split), `run_dumps.py` / `test_v25.py` / `test_v29_gc.py` /
  `test_v29_knobs.py` (8-dump raw MSE, C/B, residual, memory), `audit_v29_ns.py` (per-family
  FLOP ledger), `parity_k3v3.py` / `test_v16b.py` (parity vs the lean chain).
- `lean/` -- the float64 torch reference chain used for every closure experiment
  (`lean_k3.py`, `lean_k3_aug.py`, `g_regen_probe.py`, `lean_k3_ablate.py`). It imports the
  term tables of ARC's reference implementation
  (https://github.com/alignment-research-center/mlp_cumulant_propagation, MIT) via
  `dump_k3_tables2.py` / `k3_tables2.py`.
- `docs/` -- the write-up (`community_post.md`), the ablation table, the claims-with-evidence
  list, the derivation-to-code map, figures, the V29 cost ledger log, and the research log.

## How to read the findings log

`docs/findings_log.md` is the raw, append-only research diary the write-up is built from:
~90 numbered entries (F1..F88, plus a few decisions and hypotheses), each dated, each with
the script, log file and numbers behind it. It is unedited: internal paths
(`C:/kaggle_local/...`, `scratch/`, `runs/`) refer to the author's machine, and Phase 1
entries (F1-F39, a different network shape) are kept for completeness. Start from
`docs/findings_index.md`, which lists every entry with its headline, status and the line
number in the log, then jump to the entry. The write-up cites entries by their F-number.
The ones that matter most for Phase 2: F63 (exact 7 -> 4 restructure), F68 (kappa4
regeneration law), F69 (D21 feedback), F71 (final-layer trim, eps^2 law), F72/F73 (age-rank
law of the shared subspace), F75 (adaptive lambda), F79-F81 (Strassen and residual
engineering), F86 (cost anatomy), F88 (the floor); the dead ends are F46/F47, F55, F58,
F60-F62, F64-F67, F74, F76, F78, F82, F87.

## Reproduce the headline numbers

```
pip install --upgrade "flopscope>=0.12.0" "whestbench>=0.16.0"   # Phase 2 toolchain
git clone https://github.com/AIcrowd/whest-starterkit && cd whest-starterkit
cp <this repo>/estimators/estimator_v29.py estimator.py
uv run whest validate --estimator estimator.py
uv run whest run --estimator estimator.py \
   --dataset hf://aicrowd/arc-whestbench-public-2026@v2-phase2 --split mini --runner local
```

Expect (100 public MLPs): raw ~2.2e-8, C/B 0.2526 steady, residual ~0.29 s/MLP on a
1-core-class budget. The 8-dump numbers in the write-up come from `harness/run_dumps.py`
after `harness/dump_mini_mlps_p2.py` (needs the HF dataset and ~1e9 MC samples per MLP; the
dumps are 62 MB each and are not in this repo).

Local machine notes: the grader gives the estimator one physical core and 8 GB; residual
(non-flopscope) wall time is capped at 400 ms per MLP and setup at 5 s for the whole
submission. Test with restricted threads before shipping anything.
